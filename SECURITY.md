# Security Policy

## Supported versions

Security fixes are targeted at the latest version on `main` of repositories created from this template.

## Reporting a vulnerability

Use **Security → Report a vulnerability** if private reporting is available. Otherwise, open a public issue without exploit details to request private contact.

If you created a new project from this template, replace this policy with the project's supported versions, maintenance contact, and private reporting process. Do not post credentials or customer data in public issues.

## Baseline checks

Template workflows provide CI and repository scanning. Before deploying a new project, enable dependency security updates and add language-specific tests and required status checks once the initial workflows are passing.
